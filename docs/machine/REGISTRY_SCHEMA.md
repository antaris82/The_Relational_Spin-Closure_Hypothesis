# Machine-readable registry schema

`docs/machine/SCHEMA_VERSION` = `1`.

This file documents the enumerations used by the machine-readable snapshot, including the
fields introduced by the Task-40 release hardening.  Everything here is enforced by
`audit/verify_documentation_snapshot.py`.

---

## THEOREM_REGISTRY.jsonl

The file keeps its historical name but holds every *registered declaration*, each labelled by
kind.  A definition is never presented as a proof.

| field | meaning |
| --- | --- |
| `declaration_kind` | read from the source text by `audit/lean_statement.py` |
| `proof_status` | `PROVED` for `theorem`/`lemma`; `CONSTRUCTED` for everything else |
| `statement_text` | copied from the Lean source, never rewritten by hand |
| `statement_extraction_status` | `OK` or `UNRELIABLE` (Task 41); an extraction that fails the conservative checks is marked, never replaced by an invented statement |
| `axiom_audit_status` | `PASS` if the declaration appears in `AXIOM_AUDIT.json`, else `NOT_AUDITED` |

The extractor (`audit/lean_statement.py`) copies the declaration text up to the body delimiter.
Since Task 41 it skips a `:=` that belongs to a term-level binder (`have`, `haveI`, `let`,
`letI`, `suffices`) occurring inside the *result type*, so that a statement such as
`tangentTransition_eq_derivative_baseTransition` is no longer truncated at its internal
`haveI ... :=`.  The regression test is `python3 audit/test_statement_extraction.py`.

`declaration_kind` ∈ `{theorem, lemma, definition, structure, abbreviation, instance}`.

Validator rules:

* the declared kind must match the keyword that opens the declaration in the source file;
* a `theorem`/`lemma` entry must have `proof_status = PROVED`;
* a non-proof entry must **not** have `proof_status = PROVED`;
* every claim with a PROVED-like status must be supported by at least one entry of kind
  `theorem` or `lemma` (unless its classification is one of `primitive_datum`, `construction`,
  `interpretation`, `blocker`, `open_question`);
* a claim with status `OPEN` or `INFRASTRUCTURE_BLOCKED` must **not** carry theorem support.

## CLAIM_REGISTRY.jsonl

`formal_status` ∈ `{PROVED, PROVED_PROJECT_NATIVE, CONSTRUCTED_CONTROL, DOCUMENTED_ONLY,
INFRASTRUCTURE_BLOCKED, OPEN, NEGATIVE_CONTROL, HISTORICAL}`.

PROVED-like = `{PROVED, PROVED_PROJECT_NATIVE, CONSTRUCTED_CONTROL, NEGATIVE_CONTROL}`.

`supporting_theorem_ids` may contain **only** registered declarations of kind `theorem` or
`lemma`; the validator rejects a definition there (Task 41 / ISSUE-41-02).  The optional field
`supporting_construction_ids` holds the registered *definitions* a claim is about; every ID in
it must resolve to a registered declaration that is **not** a `theorem`/`lemma`.  It is a
reference list only and never counts as proof support.

A claim about an explicitly selected control direction carries the two optional fields
`canonical_status: SELECTED_CONTROL` and `exhaustive: false` (Task 41 / ISSUE-41-04); currently
only `CLAIM-L010`.

## OBJECT_REGISTRY.jsonl

Three separate fields distinguish *what kind of datum an object is*, *how its definition
arises*, and *whether an instance is known to exist*.  The last distinction exists precisely so
that a future reader cannot infer "`SmoothTangentSolderData` always exists" from the fact that
its type is constructed.

`canonical_status`:

| value | meaning |
| --- | --- |
| `PRIMITIVE` | a genuinely primitive local input of the project |
| `DERIVED` | constructed from earlier data, with no further input |
| `ADDITIONAL_GLOBAL_DATUM` | supplied at the global layer; not derivable from the local core |
| `GATE_DATA` | an additional comparison datum whose inhabitance is a gate of the theory |
| `CONTROL_MODEL` | an explicitly constructed control instance; nothing general follows from it |

`definition_status` ∈ `{PRIMITIVE, DERIVED}` — whether the *type/definition* is primitive or
constructed.

`existence_status`:

| value | meaning |
| --- | --- |
| `PRIMITIVE_INPUT` | the object *is* the input |
| `DERIVED_WITH_THE_DEFINITION` | an instance is produced outright by the construction |
| `SUPPLIED_DATUM` | an instance is an input of the global layer |
| `NOT_DERIVED_GATE` | the type is constructed, but inhabitance is **not** derived and can fail |
| `EXPLICIT_CONTROL_INSTANCE` | one explicitly built instance, used as a control |

Every `GATE_DATA` object must also carry a free-text `existence_note`.

Since Task 41 an object that is a **deliberately selected control direction** rather than a
canonical derived structure carries three further fields: `selection_status: SELECTED_CONTROL`,
`exhaustive: false` and a free-text `selection_note` naming the selected direction.  They are
carried by `Task37.Deformation.transportState`, `projectedTransportState` and `paraMap`
(OBJ-031, OBJ-032, OBJ-033), whose family is generated by the chosen Clifford direction
`cle 0`; the family is listed under `control_specific_data` in `PROJECT_STATE.json`, not under
`derived_local_structures`.

## PROJECT_STATE.json — taxonomy keys

| key | contents |
| --- | --- |
| `primitive_local_input` | only objects whose `canonical_status` is `PRIMITIVE` |
| `derived_local_structures` | everything constructed from the primitive local input |
| `additional_global_data` | data supplied at the global layer |
| `global_regularization_or_gate_data` | comparison data whose inhabitance is a gate |
| `derived_global_structures` | outputs of the global layer; solder-dependent entries are marked `[CONDITIONAL …]` |
| `control_specific_data` | explicitly constructed control models and witnesses |

`next_phase_open_edges` lists the missing bridges with their claim and open-problem IDs.

## MODULE_REGISTRY.jsonl

`layer` ∈ `{primitive, local_lorentz, clifford, spin, gluing, manifold, tangent, solder,
topology_control, deformation, smoketest, closure, audit}`; `status` = `FROZEN`.

## OPEN_PROBLEMS.jsonl

`blocker_type` ∈ `{INFRASTRUCTURE, MISSING_THEORY, SCOPE}`.

## MATHEMATICAL_DAG.json

Nodes carry `status = CERTIFIED`: every node is an object or a declaration that exists in the
repository.  Missing structures are **not** nodes and their bridges are **not** edges; they are
listed in `open_edges`, each with `status = OPEN`, a `claim_id` and a `problem_id`.  In
particular there is no edge `Lie(SpinGroup) → gB`, because no such theorem exists.

## Overclaim sentinels

`audit/verify_documentation_snapshot.py` rejects a canonical document containing any of

```text
no Lie algebra
spinCover ∘ ω
transition-cocycle deformations are pure gauge
transition-cocycle deformation is a change of trivialisation
regular solder always exists
Spin cocycle is only continuous                        (Task 41)
merely continuous Spin cocycle                         (Task 41)
native Spin transition datum is only continuous        (Task 41)
would require smooth Spin transition                   (Task 41)
requires smooth native Spin transitions                (Task 41)
the unique native Spin deformation                     (Task 41)
canonically selected by the primitive Euclidean input  (Task 41)
classifies the full Spin deformation space             (Task 41)
canonical deformation direction                        (Task 41)
```

They are permitted only in the two documents whose purpose is to quote and withdraw them:
`docs/paper/PAPER_I_DO_NOT_CLAIM.md` and the superseded stub
`TASK39_CONNECTION_TRANSPORT_GATE_HANDOFF.md`.

## Manifest hashes

`SOURCE_MANIFEST.json` records size and SHA-256 of every Lean source file under
`RequestProject/Spine` and of every canonical/machine documentation file;
`RELEASE_MANIFEST.json` records the SHA-256 of the source manifest and of the machine snapshot.
The validator recomputes all of them and reports the number of hashed files and the number of
mismatches, which must be zero.
